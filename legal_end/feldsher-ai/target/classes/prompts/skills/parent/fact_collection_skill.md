# 案情问题采集父Skill

## Skill定义
这是所有案情问题采集类Skill的父Skill，定义了问题采集的通用框架和标准。

## 通用问题模板

### 问题类型一：时间相关问题
```json
{
  "questionTemplate": "【事件】是什么时候发生的？",
  "options": [
    "1个月以内",
    "1-6个月",
    "6个月-1年",
    "1年以上",
    "暂不选择"
  ],
  "followUp": "具体时间是____年____月"
}
```

### 问题类型二：主体相关问题
```json
{
  "questionTemplate": "涉及的当事人有哪些？",
  "options": [
    "仅您本人",
    "您和对方两个人",
    "多方参与（3人及以上）",
    "有单位/公司参与",
    "暂不选择"
  ],
  "followUp": "请简要说明各方关系："
}
```

### 问题类型三：证据相关问题
```json
{
  "questionTemplate": "您目前掌握哪些证据材料？",
  "options": [
    "有书面合同/协议",
    "有聊天记录/通话录音",
    "有转账记录/支付凭证",
    "有证人可以作证",
    "没有证据",
    "暂不选择"
  ],
  "followUp": "请具体说明证据情况："
}
```

### 问题类型四：进展相关问题
```json
{
  "questionTemplate": "目前事情处于什么阶段？",
  "options": [
    "刚发生，还未采取任何行动",
    "已与对方协商过",
    "已向有关部门反映/投诉",
    "已报警/报案",
    "已起诉/申请仲裁",
    "暂不选择"
  ],
  "followUp": "请说明具体进展情况："
}
```

## 问题设计原则

### 1. 选项设计原则
- 选项之间互斥，不重叠
- 覆盖绝大多数常见情况
- 最后一项始终为"暂不选择"
- 选项数量控制在2-5个

### 2. 问题排序原则
- 先问核心事实问题
- 后问细节补充问题
- 按照时间逻辑顺序排列
- 简单问题在前，复杂问题在后

### 3. 问题数量控制
- 简单案件：3-4个问题
- 复杂案件：5-6个问题
- 最多不超过6个问题

## 子Skill继承规范

每个子Skill（按案由划分）需要：
1. 继承本父Skill的通用问题框架
2. 根据案由特点，定制专属问题
3. 通用问题和专属问题的比例约为1:1
4. 保持输出格式一致
